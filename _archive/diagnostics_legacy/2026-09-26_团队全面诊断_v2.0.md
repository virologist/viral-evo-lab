## 第一部分 · 问题诊断（v2.0 增量：D8-D12）

### D8【重要·新】外部改动无监控——专家包完整性存在盲区
settings.json 于 09-23 前后被外部删除（推测：WorkBuddy 应用更新/清理/同步），**13 天无人发现**，直到 09-26 validate 报错才暴露。专家包无完整性校验机制（无文件哈希清单、无定期 validate 巡检）。同类风险：plugin.json/agents MD 的任何外部漂移都可能静默发生。
**量级**：本轮是 settings.json（低危，重建即愈）；若是 plugin.json 被删则整个专家消失。

### D9【中·新】红队→修复的衔接靠人肉记忆，闭环链无自动登记
P0-4 反馈路由设计了"审查结论→分派修复"，当日实际运转良好，但存在两个手工断点：①红队矩阵与修复 commit 之间的映射靠我在 commit message 里手写引用（无结构化 trace_id）②"红队 P0 闭环率 4/4"是我人工数出来的，无自动统计。红队报告→P0 闭环报告是两份独立文件，一致性靠人维持。

### D10【中·新】慢通道的 token/时长成本未计量
首跑实测最长 5m49s，但**没有记录 token 消耗**（v1.0 设计的三方量指标缺了第一量）。4 攻击员并行 38 条攻击的产出/成本比无法量化，无法回答"慢通道值不值得每次跑"——当前只能靠定性判断（锋利度明显更高）。

### D11【低·新】分析模块（M17 型）的"校准门"缺制度化
M17 交付时实测口径偏差（freq_4h 0.9697 vs 0.917），我在 README 里写了"校准前禁跑后续步骤"——但这是**自觉纪律**，不是机制。若换一个会话/换一个执行者，无 gates 拦截未校准就建树浪费数小时算力。quality_gates 覆盖了统计阈值，未覆盖"复现校准"这一类门。

### D12【低·新】05_Glycosylation 源表的结构脆弱性（上游债务）
实测发现 metadata 有重复 SeqName（merge 膨胀 2515→2551）、位点列用氨基酸字符而非布尔。这不是团队问题，是**数据基建债务**：每个新模块（M17-M22）都要重新踩一遍这两个坑。

## 第二部分 · 改进方案（增量五项，延续"最小修改"）

### 方案 R1 · 专家包完整性巡检（治 D8）
新增轻量机制（不加角色）：在**每次慢通道启动前**强制跑一次 `validate_expert.py`（约 2 秒），结果作为红队报告的固定头部字段。另建 `integrity_manifest.json`（文件名+行数+修改时间清单，随包 commit），每次 git push 前用脚本 diff。**成本**：每任务 +5 秒；**收益**：外部漂移最迟在下次使用时暴露，且可 git 定位漂移时间。

### 方案 R2 · 红队闭环结构化登记（治 D9）
固化一个 `redteam_ledger.csv`（append-only）：`trace_id, finding_id, 严重度, 修复 commit, 闭环状态, 闭环日期`。红队矩阵落盘时同步登记 finding，修复 commit 时回填。闭环率由脚本统计而非人肉数。**成本**：一次脚本 + 每次 +1 行登记；**收益**：D9 两个断点同时消除，三方量第三量（P0 闭环率）自动化。

### 方案 R3 · 慢通道成本计量（治 D10）
红队报告头部增加固定字段：`spawn 数 / 总时长 / [token 若平台可读]`。token 不可读则先记录可测代理量（时长×攻击员数=攻击员·分钟）。**成本**：+1 行；**收益**：积累 3-5 次后可定量回答"慢通道性价比"。

### 方案 R4 · 复现校准门制度化（治 D11）
在 `context_stack/quality_gates.md`（注意：其权威源在 skills/references/，需双处同步）新增门控类目：**"复现类模块（M17-M22）必须先通过基线复现校准（关键统计量与论文锁定值差异 <预指定阈值）方可进入下游计算"**。未过门 = 与 ESS<200 同级的暂停条件。**成本**：1 条规则；**收益**：防未校准长跑烧算力。

### 方案 R5 · 主理人 MD 价值明确化（微调，不动角色）
不删除（专家中心入口+慢通道模板仍是刚需），但把其"日常路由"职能的描述降级为"慢通道激活时的编排规范"，避免后来者误以为日常必须经它。改动 3-5 行。**成本**：最小 diff；**收益**：消除利用率最低角色带来的"是否冗余"疑虑。

### 明确不做的事
- **不新增角色**：当日缺口（监控/计量/登记）全部是机制不是能力，加角色只会重回 D5 超红线
- **不删除任何角色**：10 角色当日零冲突，证据不支持删
- **不再合并**：scout 吸收 bridge 后职责已饱和，进一步合并会损坍缩清晰度
