### D1【致命】协作铁律被系统性违反——全部产出都是"模拟成员发言"

### D2【致命】架构假设错配：11 个 MD 是"剧本"，不是"运行时"

- 团队从未被"选中"激活过

即：WorkBuddy 专家团的运行单元是"单次注入的 system prompt"，不存在常驻主理人调度运行时。11 角色协作剧本在没有显式 spawn 动作时只是静态文本。

## 第二部分 · 改进方案

### 总体判断 `[FRAME]`

**问题不是"角色划分不合理"，是"团队从未运行"。** 角色职责划分经静态审查是合理的（坍缩协议消解了双归属）；协作流程设计是完整的（铁律+中转+ACK）；质量与效率——无从谈起，因为没跑过。因此改造重点不是调角色，而是**让运行机制落地**，并处理双线重复。

### 方案：双轨运行制（快通道 + 慢通道）

**轨道一 · 快通道（默认，单人格）**——承认现实：
- 日常科研任务（WF1 假说/WF3 检索/WF4 方案）由**单人格**执行：首选 virus-evolution-researcher 承载（它能力密度最高且已被实战使用），viral-evo-core skill 作为其共享方法库注入
- viral-evo-lab 的角色 MD 降格为**剧本参考**：单人格执行 WF 时按对应角色 MD 的输出规范产出（保住结构化质量），但**署名如实标注"单人格执行，参照 XX 角色规范"**——废除署名造假
- 成本不变、速度不变、质量由角色规范兜底

**轨道二 · 慢通道（显式触发，真团队）**——把多 agent 用在刀刃上：
- 仅两类任务强制真实 spawn 并行：
  - **WF5 投稿前红队**（4 攻击员真并行——多视角对抗是多 agent 的不可替代场景 `[INFERRED]`）
  - **WF6 重大诊断**（勘探员+诊断员+假说官三角互查）
- 触发词显式化：用户说"全团审查/红队总攻/多角色会诊"→ 主会话用 Agent 工具真实 spawn（general-purpose 子代理 + 对应角色 MD 作为 prompt），SendMessage 回传汇编
- 其余场景禁止 spawn（防 Anthropic 记录的"简单查询 50 子智能体"失败模式 + 15× token 消耗）
