# 诊断协议
> 裴慎思主维护。诊断官审视现有方案/管线/稿件时的标准流程。
> 更新：2026-09-10（建档）

## 诊断维度（6 维扫描）

| 维度 | 核心问题 | 严重度触发条件 |
|---|---|---|
| 方法学前沿对齐 | 是否漏用关键工具？参数设置是否最优？是否过用过时工具？ | 缺关键工具=致命；参数不当=重要；版本过期=次要 |
| 数据利用效率 | 当前数据切片/抽样/子集划分是否充分利用？ | 维度未充分利用=重要；偶发未用=次要 |
| 管线协同 | 跨方法是否同树基准？前置检测是否做？交叉验证是否全？ | 重组未检测=致命；交叉验证不全=重要 |
| 统计纪律 | 多重检验是否校正？功效是否评估？是否区分"选择信号"vs"伪信号"？ | 单方法结论当双方法=致命；功效未评估=次要 |
| 可复现性 | 代码是否可独立运行？参数是否硬编码？日志是否完整？ | 硬编码路径=致命；日志缺失=重要 |
| 叙事强度 | 主线逻辑链是否清晰？图表是否支撑论断？因果 vs 相关是否区分？ | 因果vs相关混淆=重要；图表冗余=次要 |

## 严重度判定
- **致命**：推翻当前结论的核心证据 / 数据未达基础可解释性
- **重要**：影响投稿可信度但结论核心仍可立
- **次要**：优化空间，不影响结论
- **改进**：锦上添花

## 改进方案优先级映射
- 致命 → P0（必须解决，否则稿件停滞）
- 重要 → P1（建议解决）
- 次要 → P2（时间允许）
- 改进 → P3（资源允许）

## 与 WF5 投稿前红队审查的区分
| 场景 | 触发 | 角色 |
|---|---|---|
| 常态化方法审视 | 方法/方案改进/审计 | WF6（研究诊断官） |
| 投稿前总攻 | 审查/critique/投稿前 | WF5（红队矩阵） |

同一稿件：先 WF6 常态化诊断 → 修改 → WF5 投稿前总攻；不重复执行。
