# 编号与坐标映射纪律（Coordinate & Numbering Discipline）
> 建档：2026-09-30 | 触发：WF1 实测暴露的真实误判事故
> 权威级别：与 quality-gates 同级——违反本纪律产生的是**静默错误结果**，不是报错

## 一、事故原型（必读，本文件存在的理由）

2026-09-30 WF1 实测中核验 G140（mature 124）的 N-糖基化 sequon：

| 方法 | 结果 | 判定 |
|---|---|---|
| ❌ 按**比对列索引**取 `seq[123:126]` | NHT 占 0.92% | **错误**（险些得出"G140 sequon 不成立"的结论） |
| ✅ 去 gap 后按**残基位置**取第 124-126 个残基 | NHT 占 **20.26%** | 正确（与 NetNGlyc 表 21.15% 吻合） |

**根因**：多序列比对文件（`.fas`）的列索引 ≠ 序列残基编号——比对含 gap（`-`），第 N 列不是第 N 个残基。

## 二、铁律（三条）

1. **凡从比对文件取残基，必须先去 gap** —— `ungapped = seq.replace('-','').replace('X','')`，再按位置索引。**禁止**直接用 `seq[i:j]`。
2. **任何跨编号系统的换算必须显式记录换算式** —— 尤其是：
   - H5 full ↔ mature：`mature = full − 16`（NetNGlyc 体系）
   - H5 ↔ H3 ↔ H1：**不存在全局 offset**，必须逐位点查 `HA_numbering.xlsx`（H3 含 125b 类插入码，offset 在不同区段不恒定）
   - 序列残基 ↔ 结构残基（PDB）：需查 SIFTS 或结构文件 SEQRES 映射
3. **跨亚型外推一律标 [推断] 并给出落点验证** —— 落点残基的野生型若与预期不符（如预期 N 实为 P），说明映射错误，**不得**强行解释数据。

## 三、标准操作流程（SOP）

```
1. 确认目标编号体系（mature / full / H3 / PDB）
2. 若跨体系 → 查 HA_numbering.xlsx 逐位点换算，记录换算式
3. 若从比对取残基 → 去 gap 后索引（不是列索引）
4. 取到残基后做「自洽性检查」：
   - 糖基化位点：是否满足 N-X-S/T（X≠P）？
   - 已知位点：残基是否与文献一致？
   - 频率：是否与 NetNGlyc 表/论文锁定值同量级？
5. 不通过第 4 步 → 停止，报告坐标映射可疑，不要用该结果写结论
```

## 四、本项目已核验成功的映射（可直接引用）

| 位点 | mature | 去 gap 残基 | sequon | 满足率 | 交叉验证 |
|---|---|---|---|---|---|
| G70 | 54 | N54-C55-S56 | N-C-S ✓ | 4.81% | NetNGlyc 表 4.89% ✓ |
| G140 | 124 | **N124-H125-T126** | N-H-T ✓ | **20.26%** | NetNGlyc 表 21.15% ✓ |

> 该结果**不依赖 H3↔H5 映射**（纯序列事实），可直接用于解除 DMS 数据的编号碰撞阻塞。

## 五、已知未解决（标注，不要假装已解）

- **H3↔H5 offset**：论文唯一锚点 A160T(H3)=A156T(H5) 给 offset −4，外推 124→H3 128 落点 P128S，但 H3-128 野生型为 P（非 sequon 的 N）→ **offset 在该区段可能不恒定**，DMS 数据的跨亚型索引**暂不可用**，凡依赖它的预测挂 P0 阻塞。
- 解法建议：绕过编号映射，直接用 H5 mature 编号查 sequon（本项目已验证可行）。
